## Architecture

**Stack:** React 19 + Vite + Tailwind CSS + Three.js (react-three/fiber) + Supabase (Auth + Postgres) + TanStack Query + react-helmet-async

**Repo:** `github.com/novautomatic/WebNexCommit` (owner: novautomatic). Deployed on Vercel at `https://www.nexcommit.com`.

**Routes (`src/App.jsx`):**
- `/` - `Home.jsx`: 3D hero, services, client portfolio (`src/data/CLIENTS.js`), FAQ, CTA
- `/servicios`, `/servicios/:slug` - `ServicesIndex.jsx` / `Services.jsx`, content in `src/data/SERVICE_PAGES.js`
- `/blog`, `/blog/:slug` - `pages/blog/BlogList.tsx` / `BlogPost.tsx`
- `/lp/:slug` - `AdLanding.jsx`: Google Ads landing pages (noindex), content in `src/data/ADS_LANDINGS.js`
- `/login` - Supabase email/password login
- `/admin` - protected (`ProtectedRoute`), lazy-loaded `Admin.jsx` with tabs Blog (`BlogAdmin.tsx`) and Cotizador (`Cotizador.jsx`, data in `PROJECT_MODULES` / `SERVICE_CATEGORIES` / `PROJECT_PRICING`). Team shortcuts/links live in the Tareas → Accesos sub-tab (`?tab=tareas&vista=accesos`, `pages/configuracion/ConfiguracionAdmin.jsx`; stored in table `accesos_directos`, migration `20261007160000_accesos_directos.sql`, hooks in `src/hooks/tareas.js`; also shown as the "Accesos" dropdown in the panel header via `AccesosMenu.jsx`)
- `/privacy`, `/terms`

**Contact + tracking:**
- `src/config/contact.js` - single source for the WhatsApp/phone number, pre-filled messages, `[Google]` tag for Ads visitors (gclid), GA4 events and Google Ads conversion IDs (empty until filled from Google Ads).
- `src/components/ContactButtons.jsx` - `WhatsAppLink` and `ContactDock` (mobile bar + desktop bubble).
- GA4 (`G-FBHZGW2YB7`) loads in `index.html` with Consent Mode v2 defaulting to denied; `src/components/CookieConsent.jsx` grants it after the visitor accepts.

**Password vault (`/admin?tab=boveda`):**
- `src/pages/boveda/BovedaAdmin.jsx`, hooks in `src/hooks/boveda.js`, crypto in `src/lib/boveda.js`, migrations `20261015120000_boveda_claves.sql`, `20261015180000_boveda_compartida.sql` and `20261016120000`–`121000_boveda_2fa_*.sql` (3 parts, run in order; tables `boveda_config`, `boveda_entradas`, `boveda_codigos`, `boveda_sesiones`). ONE vault shared by the whole team (`es_equipo()`), one common master password. A random AES-GCM data key (DEK) encrypts each entry in the browser and is stored wrapped by a PBKDF2 key derived from the master password; the key lives only in React state (auto-lock after 5 min idle, on «Bloquear», or when the server session ends).
- **2-step access**: before the master password, every member must pass a 6-digit code emailed to them (`boveda_pedir_codigo` → pg_net → Agente-Next back `POST /avisos/codigo-boveda`, same secret as the other avisos; code stored only as a SHA-256 hash, 10 min, max 5 attempts, 6 per hour). `boveda_verificar_codigo` opens a 30-minute row in `boveda_sesiones`; RLS on `boveda_config` / `boveda_entradas` requires it (`boveda_verificada()`), so the database enforces it, not just the screen. The wrapped-key column `clave_respaldo` is never granted to the browser (column-level SELECT).
- **Restore by email**: on creation the browser sends the raw DEK once (`boveda_crear`) and the database stores it encrypted (pgcrypto) with the Vault secret `boveda_respaldo_secreto` (generated by migration part 1; never copy it). A dueño or the creator (`boveda_admin()`) can request a `recuperacion` code, get the DEK back via `boveda_recuperar`, re-wrap it with a new master password in the browser and save it with `boveda_cambiar_password`. Trade-off: anyone controlling the database AND that Vault secret can open the vault. Vaults created before this (no `clave_respaldo`) cannot be restored; `boveda_reiniciar` wipes them so a new one can be created.
- The panel never writes `boveda_config` directly (no INSERT/UPDATE/DELETE grants): only the `boveda_*` functions do. Never expose vault tables through the MCP server or any other service-role code.

**OpenAI costs (`/admin?tab=openai`, owners only):**
- `src/pages/openai/OpenAIAdmin.jsx` reads `GET <Agente-Next back>/nexcommit/openai/panel` (route `src/routes/nexcommitOpenai.js` in `novautomatic/back_chat_next`), which checks the NexCommit session JWT + `equipo.rol = 'dueno'` and merges: the real OpenAI bill (Costs API) and tokens per API key (Usage API) via `OPENAI_ADMIN_KEY`; chats from Agente-Next `trazas` (RPC `uso_detalle`, file `db/uso-detalle.sql`); Creator from `creador_consumo`. The Creator uses its own key `OPENAI_API_KEY_CREADOR` (same OpenAI project; falls back to `OPENAI_API_KEY`). The USD→CLP rate lives in `creador_config.usd_clp`.

**Tasks system (`/admin?tab=tareas`):**
- Schema, RLS, triggers and crons in `supabase/migrations/20261007120000_sistema_tareas.sql` (tables `equipo`, `proyectos`, `tareas`, `tarea_comentarios`, `tarea_historial`, `avisos_whatsapp`). Access = active row in `equipo` matching the session email (`es_equipo()`); only `rol = 'dueno'` edits `equipo`.
- UI in `src/pages/tareas/` (board, list, projects, team, task modal with comments/history/notices); data hooks in `src/hooks/tareas.js` with realtime refresh.
- WhatsApp notice to the assignee on create/reassign (not self-assign): trigger → `encolar_aviso_tarea()` → `pg_net` POST to Agente-Next back `/avisos/tarea` (secret in Vault `avisos_tareas_url` / `avisos_tareas_secret`) → cron `procesar-avisos-tareas` reconciles status every minute. Bulk imports use `SET LOCAL app.sin_avisos = 'on'`.
- **Delivery meetings** (`20261014150000_reunion_de_entrega.sql`): every `fecha_limite` is a team meeting at 16:00 Santiago (marked in `CalendarioVista.jsx`). Cron `reunion-entrega-diaria` → `enviar_reunion_entrega()` sends ONE email a day at 09:00 to the whole team (`POST /avisos/reunion-entrega`): today's deliveries per person, or the next meeting date, plus each person's other open tasks. Test with `SELECT public.enviar_reunion_entrega(true);`.
- **GitHub Issues is the source of truth** (`supabase/migrations/20261007150000_tareas_desde_github.sql`): tasks are born and move in GitHub; Supabase is a mirror. `github_sync_tick()` (pg_cron every minute + panel every 30 s) polls `GET /issues?filter=all&since=` with the `github_token` Vault secret and upserts `tareas`. The panel never writes `tareas` directly: RPCs `tarea_crear` / `tarea_actualizar` / `tarea_comentar` send REST (create, labels, comments) or GraphQL (title/body, close/reopen — pg_net has no PATCH) and keep an optimistic copy with `sync_estado = 'pendiente'`. Mapping: open/closed(+state_reason) and labels «en progreso» / «en revisión» / «bloqueada» → estado; «prioridad: X» → prioridad; person labels in `equipo.github_labels` (or `github_login` assignee) → responsable; body line «Fecha límite: AAAA-MM-DD» → fecha_limite. Internal NexCommit tasks live in the private repo `novautomatic/dashboard-tareas`.
- **Areas and clients** (`20261007170000_areas_y_clientes.sql`): `proyectos.tipo = 'area'` (no repo, owner in `area_responsable_id`) holds local-only tasks; the `tarea_*` RPCs are wrappers that handle areas locally and delegate to the renamed `tarea_*_github` versions otherwise (re-run this migration after re-running the GitHub one). `clientes` ↔ `proyectos` is many-to-many via `proyecto_clientes`; panel tabs Áreas and Clientes, client picker in the project form (`ClienteSelector.jsx`).
- **Client emails + consent** (`20261015120100`–`20261015122500_clientes_consentimiento_*.sql`, 6 parts, run in order): clients can only be emailed if THEY accepted (Ley 21.719). Two ways in: web (a Creador lead set to `convertido` becomes a client carrying its `acepta_terminos_at` / `acepta_marketing`, function `cliente_desde_lead`) or the "Primer correo" (`cliente_enviar_invitacion`) that links to the public landing `/confirmar-datos?c=<id>&t=<token>` (`ConfirmarDatos.jsx`, RPCs `consentimiento_ver` / `consentimiento_guardar`, token = SHA-256 of Vault `clientes_token_secret` + id + `token_version`). A trigger locks the consent columns: the panel can withdraw promotions but never grant them. Campaigns (`clientes_enviar_campana`, button "Mandar correo" in Clientes) filter `acepta_marketing` in SQL, cap 400/day (Gmail), and go through the Agente-Next back `POST /avisos/cliente-correo` (`src/lib/correosClientes.js`, List-Unsubscribe header). Proof in `cliente_consentimientos`; send log `cliente_correos` (cron `procesar-correos-clientes`, purged at 180 days).
- **MCP server for Claude** (`supabase/functions/mcp-tareas`, migrations `20261010130000`–`20261010134000_mcp_tareas_*.sql` (5 parts of <6 KB each: the Dashboard SQL editor truncates pasted text at ~8,000 chars; run them in order)): Streamable HTTP MCP with tools `listar_columnas`, `mis_tareas`, `ver_tarea`, `buscar_tarea`, `mover_tarea`, `crear_tarea` (areas only). Auth = per-member secret token in the URL (`?key=`), stored only as SHA-256 in `mcp_tokens`; create with `SELECT public.mcp_crear_token('email', 'nombre')` (shown once), revoke with `activo = false`. The function uses the service role and calls `mcp_*` SQL functions, which set the member's JWT claims (`mcp_como`) and then reuse the panel RPCs (`tarea_actualizar`, `tarea_crear`), so the column→GitHub translation, history actor and WhatsApp rules are identical. Audit in `mcp_registro` (owners can read). Deploy: `supabase functions deploy mcp-tareas --no-verify-jwt`; connector URL `https://<project>.supabase.co/functions/v1/mcp-tareas?key=<token>`.
- This repo is PUBLIC: never commit task/issue data exports or secrets (use the gitignored `Claude outputs/`).

**Key patterns:**
- **Routing:** SPA routing using `react-router-dom` with `vercel.json` rewrites for production. Any one-segment path (`/algo`) not listed in `vercel.json` is proxied to the Creador back as a client page (`/:slug` → `back-chat-next.vercel.app/creador/p/:slug`), so every new single-segment route must be added to `vercel.json` (→ `/spa`) AND to `RESERVADOS` in the back's `src/creador/slugs.js`.
- **SEO:** per-page metadata via `src/components/SEO.jsx` (react-helmet-async); `scripts/generate-sitemap.mjs` builds the sitemap. Canonical host is `https://www.nexcommit.com` (apex 308-redirects to www) — never write URLs without `www`.
- **Prerender:** `npm run build` also builds `src/entry-server.jsx` (SSR) and runs `scripts/prerender.mjs`, which writes static HTML for `/`, `/servicios[/:slug]`, `/blog`, `/privacy`, `/terms` and every `/lp/:slug` (served via `cleanUrls` in `vercel.json`). Every other route falls back to the untouched shell `dist/spa.html` (rewrite destination must be `/spa`, without `.html`: with `cleanUrls` the `.html` form 404s). Head tags baked at build carry `data-pr` and `main.jsx` removes them on boot (React 19 + helmet-async v3 append tags instead of replacing them). New public routes must be added to the list in `prerender.mjs`; components must not touch `window`/`localStorage` during render.
- **3D Hero:** Layered wireframe composition in `Hero3D.jsx` (icosahedron, dodecahedron, octahedron, particles, glow edges) wrapped in `Float`. Lazy-loaded.
- **Styling:** Brand colors via CSS variables in `:root` (ink: #071b31, brand: #248bde, sky: #67c8f3) and `.glass-dark` morphisms.
